# Аудит кода — 20 октября 2026

## Область проверки

Проверены состав сборки, цепочки запуска и закрытия, захват TCP, преобразование боевых данных в UI, уведомления, сохранение настроек, обновления и упаковка. Infrastructure компилируется по явному списку, а перенесённый Core пока целиком. Это аудит рабочего пути метра, а не подтверждение корректности каждого перенесённого типа Core.

## Исправлено

- Уведомления теперь публикуются после завершения обновления коллекции: WPF Popup не получает промежуточный список и не дублирует строки.
- События показываются одной зацикленной строкой с отдельным цветовым градиентом для каждого типа события. При скрытом метре строка живёт в отдельном окне, если включена соответствующая настройка; ярость босса из ленты убрана и помещена под HP без увеличения блока цели.
- Список участников переставляет существующие UI-строки, автоматически показывает до десяти мест без прокрутки и закрепляет локального игрока в десятой строке с его настоящим рангом, если он ниже десятого места.
- Автоматическое увеличение высоты больше не записывается как пользовательский размер: при уменьшении списка окно возвращается к высоте одной строки. Старые ошибочно сохранённые высоты мигрируют на базовое значение без потери ширины.
- Класс игрока распознаётся также по навыкам лечения и эффектов. Неизвестный класс не подменяется иконкой человека; известная классовая иконка локального игрока выделена мягким свечением. Кнопка PvE/PvP использует игровые мечи из атласа HUD.
- После смерти босса таймер ярости скрывается и больше не переживает исчезновение цели: нулевое HP сохраняется для показа `HP 0%` даже после удаления сущности. Обычная и боссовая HP-рамки выровнены по пропорциям исходных спрайтов, заливка доходит до внутренних краёв без захода на нижний декор.
- Таймер Бессмертного Гартуа считывается из пакета игровой карты и сохраняется с привязкой к серверу. Событие появляется в календаре, а в ленте — за десять минут до появления; устаревший таймер не выдаётся за подтверждённое присутствие босса.
- Очередь payload Npcap ограничена; TCP-ключ учитывает IP-адреса и порты, перекрывающиеся повторы не передают старые байты повторно, состояние соединения очищается при новом SYN и закрытии.
- Ошибки и предупреждения Npcap/парсера больше не теряются в пустом логгере. Журнал перемещён в `%LOCALAPPDATA%\Aion2Meter\logs` и ограничен 16 МиБ на запуск.
- Настройки сохраняются атомарно с резервной копией; повреждённый основной JSON восстанавливается из неё. Значения прозрачности проверяются на конечность.
- Закрытие метра освобождает захват и останавливает Npcap только если метр сам запустил службу и не запущен другой известный клиент захвата (в том числе AionFlex). Повторный запуск распознаёт уже работающий драйвер и состояние `STOP_PENDING`, чтобы не выдавать его за ошибку прав администратора.
- Ссылка обновления проверяется перед открытием; произвольный URL из ответа API не запускается.
- Версия из тега релиза передаётся в `dotnet publish`, чтобы версия установщика и EXE не расходились. Скрипт выпуска проверяет пути перед очисткой staging-каталога.

## Проверка

- `dotnet build Aion2Meter.slnx -c Release` в отдельный audit-каталог: без ошибок и предупреждений обычной сборки.
- `tests/Aion2Meter.Smoke`: 74 проверки пройдены (коллекции, рост и обратное сужение окна, цвета событий и HP, ярость отдельно от ленты, закрытие босса и сохранение `HP 0%`, TCP, настройки, календарь и таймер карты, одиночный экземпляр, диагностический лог, состояние Npcap).
- PowerShell-парсер: `publish.ps1`, `prepare-inno.ps1`, `install.ps1` без синтаксических ошибок.
- `git diff --check`: без ошибок пробелов.

## Что остаётся проверить отдельно

- Живой бой с более чем четырьмя участниками: автоматический рост окна пока подтверждён алгоритмом и тестом, но не игровым наблюдением.
- Захват на конкретных сетевых адаптерах, установка Npcap и обновление через Inno Setup требуют отдельного end-to-end прогона на машине пользователя; этот проход не заменяет его.
- Большой перенесённый `DpsPacketParser` и неиспользуемая часть Core требуют отдельного выделения протокольных модулей и эталонных packet-replay тестов. Механически удалять эти файлы нельзя: их зависимости не отделены, а поведение декодера может измениться незаметно.
